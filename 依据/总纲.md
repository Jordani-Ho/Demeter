# 总纲

本文件只放能写成代码、能检查的东西。为什么这样做、我们相信什么，见《缘起》。

总纲只有三样根：**人、关系、天地人**。下面每一条都从这三样根推出来；推不出来、只在某个领域成立的，写在那个领域的子纲里。

---

## 一、人

1. 一个人可以有多个智能体，每个智能体对应他的一面（他在某段关系里的角色）。
2. 智能体替主人定下一个，不给主人一堆选择。
3. 对外的承诺（下单、付钱、约定）要落到现实，由本人确认；智能体可以起草，不能代为确认。
   - 推自：智能体是人在虚拟世界的一面，现实里的承诺属于现实里的那一面。

## 二、关系

1. 关系只有两种：**学**和**换**。
2. 一次交互里如果两种都有，就拆开：学的部分按“学”处理，换的部分按“换”处理。

### 学

| 一方 | 做什么 |
| :-- | :-- |
| **知识库** | 只讲“这样东西是什么”，不知道学的人是谁 |
| **教的一方** | 用知识库，按学的一方交来的参数，给出两三个方案 |
| **学的一方**（主人的智能体） | 交出参数，从方案里替主人定下一个 |

- 三方可以来自不同的人，可以互相替换。
- 学的一方只交出对方需要的那部分参数；教的一方只收参数，不记是谁。
- 没有考试，不回传：主人的感受（点赞、收藏）只给自己的智能体用；教的一方看不到这些数，也不设排行。
- 换哪一位教的一方，由学的一方自己定。

### 换

1. 钱和货只在人与人之间走，平台不经手。
   - 推自第六节：经手，就是坐到了中间。
2. 账由当事人各自的智能体记。
3. 各个子纲可以有自己的价值尺度。

## 三、天地人

1. 每条记录都带三样：**时**（当地的时间与时节）、**地**（在哪里）、**人**（是谁）。
2. 天和地是参数，人的活动以它们为准。
3. 用什么单位表示时间（时辰节气，还是钟点季节），由各个子纲自己定。

## 四、智能体的组成

| | 内容 | 会不会变 |
| :-- | :-- | :-- |
| **先天** | 五个本能；一个技能插口；守所在子纲的律 | 不变，所有智能体都一样 |
| **后天** | 本人库、跟过哪些教的一方、插了哪些技能、说话的方式和样子 | 跟着主人变 |

- **五个本能**：
  - **记**：记住主人和他照看的人；
  - **看**：看天和地；
  - **学**：向教的一方学；
  - **定**：替主人定下一个；
  - **换**：去交换，例如买。
- **本人库**由智能体自己修改，不让人填表；只在主人手里。
- **插口**：谁都可以做技能；技能只能加本事，不能改先天，也要守所在子纲的律。各子纲共用一个插口。
- 主人想要，才生出智能体。

## 五、三条流和一张地图

1. 三条流：**信息流**、**物流**、**资金流**。
2. 三条流落在同一张地图上，每个子纲一个图层。
3. 同一个人的信息从一个子纲传到另一个子纲，第一次要本人同意。

## 六、没有中心

1. 公共设施（中继、目录、地图）谁都能架，可以互相替换；我们架的那一份没有特权。
2. 不集中保存个人的资料，不设集中的排行。

## 七、只管虚拟世界

1. 智能体只对虚拟世界负责。
2. 不为现实世界的法律、合规加规则，也不为此加代码；这些由现实里的人把握。

## 八、纲、律、数

| 层 | 是什么 | 写在哪里 |
| :-- | :-- | :-- |
| **纲** | 本文件 | 总纲 |
| **律** | 智能体可以执行、可以检查的行为规则；红线也在这一层 | 子纲 |
| **数** | 律里的具体数值 | 子纲和产品，运营中观察后调整 |

- 总纲不设红线：它和现实世界之间没有接口。子纲和现实有接口（钱、货、健康、人身），红线由子纲定，可以比总纲细得多、严得多。
- 纲和律里只写代码能做到、能检查的话。

## 九、层级

| 层 | 内容 | 在哪里做 |
| :-- | :-- | :-- |
| **总纲** | 本文件 | 总架构的对话 |
| **子纲** | 医、衣、食、住、行各一份：总纲在这个领域里是什么，加上本领域的律 | 衣食住行在总架构的对话；医在知衡的对话 |
| **产品** | 一个个具体的产品 | 每个产品各开一个对话 |

1. 下一层只能细化上一层，不能违背上一层。
2. 每个产品动手之前，先读总纲和本领域的子纲。
3. 下一层发现上层有问题，带回总架构，不在下一层自己改。带回来的分三种，由总架构处理：
   - **误解**：下一层读错了上层，不予理会；
   - **冲突**：两层说法打架，划清边界，写明各管哪里；
   - **建议**：可以接受，也可以拒绝。
4. 总纲由发起人和总架构师修改。
